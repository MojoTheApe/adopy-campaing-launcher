# Worker общего журнала действий ACL (ACL-2347)

Принимает пачки событий от машин, кладёт каждую отдельным неизменяемым объектом в R2 и отдаёт их владельцу. Разворачивает владелец: у исполнителя доступа к Cloudflare нет.

## Что нужно

- аккаунт Cloudflare и `wrangler` (`npm i -g wrangler`, затем `wrangler login`);
- токен библиотеки команды (`ACL_LIBRARY_TOKEN`): он же авторизует запись, Worker проверяет его запросом к GitHub `GET /repos/MojoTheApe/acl-lib`.

## Развёртывание

Все команды из папки `deploy/event-log`.

1. Бакет для событий:

   ```
   wrangler r2 bucket create acl-event-log
   ```

2. KV для записей о токенах (хранится только sha256 токена, сам токен нигде не лежит):

   ```
   wrangler kv namespace create AUTH
   ```

   Команда напечатает `id`. Впишите его в `wrangler.toml` вместо `REPLACE_WITH_KV_NAMESPACE_ID`.

3. Ключ чтения, только у вас. Придумайте длинную случайную строку:

   ```
   wrangler secret put READ_KEY
   ```

4. Выкладка:

   ```
   wrangler deploy
   ```

   В конце wrangler напечатает адрес вида `https://acl-event-log.<ваш-аккаунт>.workers.dev`.

5. Проверка, что чтение закрыто (должно быть `401`):

   ```
   curl -i https://acl-event-log.<ваш-аккаунт>.workers.dev/v1/list
   ```

## Куда вписать адрес

- В код: константа `DEFAULT_URL` в `src/acl_event_log/shipper.py`. После этого машины, получившие обновление, начнут отправку сами. Пока адрес пуст, события копятся локально и никуда не уходят.
- На своей машине, для чтения, задайте в `.env` (или переменных окружения):

  ```
  ACL_EVENT_LOG_URL=https://acl-event-log.<ваш-аккаунт>.workers.dev
  ACL_EVENT_LOG_READ_KEY=<тот же READ_KEY>
  ```

Дальше: `python scripts/acl_log_pull.py` скачивает новое в локальную SQLite, `python scripts/acl_log_report.py --runs` показывает прогоны.

## Первая проверка на настоящем токене

Проверка токена опирается на то, что токен библиотеки видит репозиторий `acl-lib` через `GET /repos/...`. Это ещё не проверялось на настоящем токене. Если токен не может прочитать этот репозиторий через API, Worker ответит `401` всем машинам. Тогда не обходите проверку: сообщите об этом, события при этом не теряются, они остаются в локальном ящике каждой машины.

Быстрая проверка с вашей машины (подставьте токен в переменную, не в историю команд):

```
curl -i -X POST https://acl-event-log.<ваш-аккаунт>.workers.dev/v1/batch -H "Authorization: Bearer %ACL_LIBRARY_TOKEN%"
```

Ответ `400` (плохие заголовки) значит, что токен принят; `401` значит, что нет.

## Контракт

| Запрос | Кто | Ответы |
|---|---|---|
| `POST /v1/batch` (gzip, заголовки `X-ACL-Machine`, `X-ACL-Batch`) | машина, `Bearer <ACL_LIBRARY_TOKEN>` | `200` (в том числе «уже есть»), `400`, `401`, `413`, `503` |
| `GET /v1/list?cursor=&prefix=` | владелец, `Bearer <READ_KEY>` | `{"keys": [...], "cursor": "..."\|null}` |
| `GET /v1/object?key=` | владелец, `Bearer <READ_KEY>` | тело объекта |

Ключ объекта: `v1/dt=<дата приёма UTC>/machine=<машина>/<пачка>.ndjson.gz`. Повторная пачка ничего не перезаписывает. Токен проверяется заново раз в час; если GitHub недоступен, рабочая машина продолжает писать по записи не старше суток.
