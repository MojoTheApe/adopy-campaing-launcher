## Findings

Produced a comprehensive service architecture spec at
`artifacts/specs/service-architecture.md` covering all 8
requirements. Key design decisions:

1. **Data model (§2):** 13 SQLAlchemy async models replacing all
   Excel I/O. `campaign_stats` + `stats_import` replace the stats
   Excel; `reference_data` (with category+key+JSON pattern) replaces
   all sheets in Upluad FB.xlsx; `kb_target`/`kb_offer`/`kb_creative`
   replace knowledge_base.json; `combo` + `analysis_run` persist
   analysis results; `chat_conversation` + `chat_message` store
   AI conversations.

2. **API surface (§3):** 30+ REST endpoints under `/api/v1/`
   organized by domain (stats, analysis, upload, kb, reference,
   chat, rules, health). All endpoints documented with Pydantic
   request/response schemas. OpenAPI auto-generated by FastAPI.

3. **AI agent (§4):** Custom wrapper over Claude SDK with 7
   tool definitions mapping to service-layer functions. Streaming
   via SSE. Conversation persistence in DB. ~300 lines of code,
   no framework dependency.

4. **Web app (§5):** 10 pages with Jinja2+HTMX+Tailwind. HTMX
   for interactivity (analysis triggers, table updates), SSE
   for chat streaming. Zero JS framework — only ~50 lines of
   vanilla JS for SSE handling.

5. **Deployment (§6):** Single Docker container with mounted
   volume for SQLite + files. 10 env vars for configuration.
   Per-customer isolation at Docker level (one container per
   customer).

6. **Migration (§7):** Core pandas pipeline (compute_metrics →
   enrich_structure → aggregate_combos) is unchanged — only the
   I/O layer changes. `load_reference_data()` gets a DB-backed
   drop-in replacement returning the same dict structure. KB
   lookups move from file reads to SQL queries with same
   resolution logic.

7. **Project structure (§8):** Clean layered architecture —
   `core/` (pure logic, DataFrame-based), `services/` (DB-aware
   wrappers), `api/routes/` (thin HTTP handlers), `web/` (HTML
   routes), `agent/` (LLM integration).
