## ACL-2583 — A failed read of the journal's campaign no longer counts as "campaign gone" — 2026-11-12

Depends on ACL-1856 (#1569) and ACL-2578 (#1580).

When a publish finds an earlier operation in the journal, it reads that campaign by id. Before, any failed read (timeout, rate limit, Meta 5xx) was taken as "the campaign is gone" and a new operation started, which could create a second campaign next to a live one. Now only Meta's definite "does not exist" answer (code 100 / subcode 33) or a DELETED/ARCHIVED status counts as gone. A read that fails any other way (timeout, Meta 5xx, code 1/2) is retried 2-3 times over about 30 s; if Meta still does not answer, the publish does not stop: it continues as a new operation under a distinct `<name> copy N` name (a possible duplicate is accepted, the same name is never reused) and says so in a warning. Rate limits (codes 4/17) stay a stop.
Publishing no longer asks the buyer to wait: a campaign that is alive by id with the recorded name is always resumed (no lag window), and a write whose result is unknown is read back once more after the same ~30 s pause and, if Meta still does not have it, written again (a duplicate is possible; objects are PAUSED). Only Meta's own refusals such as rate limits stop a publish.
