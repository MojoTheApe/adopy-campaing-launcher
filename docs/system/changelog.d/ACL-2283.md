## ACL-2283 — Requeue a failed profile start under machine load — 2026-10-28

A job whose profile start failed with "page_unresponsive" on the first start, or "profile closed while the action was starting", while the machine is loaded (CPU at or above 85%, free memory below what one more profile needs, or other profiles still warming up; local readings only) no longer stops. It goes back to the queue (yellow, "the machine is busy ... starts again by itself", with live CPU and memory numbers) and starts again once the load drops (CPU below 70%), at least 15 s and at most 3 min between starts, with no attempt limit; Stop cancels it. No 10-minute pause and no stop report is created for such a failure. A frozen tab on an otherwise idle machine, a failure after a write to Meta and every other failure stop as before. The wait keeps the silence watcher quiet and writes `load_requeue` / `resource_wait` rows.
