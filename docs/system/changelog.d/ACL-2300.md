## ACL-2300 — Release a stale Multilogin lock before starting a profile — 2026-10-29

After the owner stopped a profile by hand, Multilogin X showed it as "Locked" and our start failed with "HTTP 500: can't lock profile". When a start answers "can't lock", no browser process of the profile runs on this machine and Multilogin (`GET /api/v1/profile/statuses`) does not list the profile as active, the robot now releases the lock once through the launcher's documented stop call and starts the profile once more, inside Multilogin only. If the release fails or the profile is still locked, the run stops with a message asking to open the profile once in MLX Desktop (click "Locked"). A profile running here keeps the "opened by hand" rules; other start errors are unchanged. The release is written to telemetry (`profile_lock_released`) and shown as a step.
