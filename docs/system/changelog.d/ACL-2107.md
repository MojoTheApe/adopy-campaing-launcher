## ACL-2107 — Release delivery no longer fails on flaky GitHub run listing — 2026-10-22

Delivery of batch #1104 stopped with "neither ran the full test matrix" although a full run of the tree
existed: the `head_sha` run list from GitHub sometimes comes back empty and an error in `commits/<sha>/pulls`
was swallowed as "no PR". The scope job now records the ids of the runs it reused in an `acl-reused-runs`
annotation, and `verify_promotion` fetches those runs directly by id (`actions/runs/<id>`) and checks them
exactly as before (head, tree annotation, PR binding, jobs, full matrix incl. Python 3.11). An empty run list
is retried with a pause, and an API error in the PR binding at the release gate is retried and then reported as
"could not be proven", never as "no PR". Extra safety: combined batch PRs (`codex/batch-*` or a
`Tracker batch:` line) always run the full matrix and never borrow jobs; source PRs keep the ACL-1649 rule.
Check names and the release gate are unchanged.
