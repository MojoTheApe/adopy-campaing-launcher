## ACL-2299 — Tabs that freeze under load: restored tabs closed, busy-machine waits — 2026-10-29

Robot profile start now closes the Ads Manager tabs the profile restored (only Ads Manager pages of the profile's own browser context; the tab we drive and every other tab are kept) and logs `page_count` before and after in `fb_api_tab_context`. A tab that stops answering in the middle of a job while the machine is busy (same CPU reading as ACL-2283 B) is waited for up to the patient limit instead of stopping at once: a read is asked again, a write only waits before it is sent (an already-sent write is still reconciled by the caller, never resent). On an idle machine the ACL-2262 stop and pause stay. Check plan, which writes nothing, waits on any machine. Waits beat the silence watcher (no `step_stuck`). Stop rows carry CPU %, memory % and page counts.
