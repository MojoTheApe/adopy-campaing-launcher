## ACL-2578 — Readback accepts Meta's image-name suffix; a re-run reuses its left-over and never repeats a campaign name — 2026-11-12

Depends on ACL-1856 (#1569).

Readback no longer flags an image whose library name Meta stored with a `_<digits>` suffix (a different image still fails). A re-run after a stop now reuses its own left-over campaign and ad set when their settings match the builder, even if the creatives were replaced or added: for a campaign that has no ads yet, Meta's derived placement aggregate (`advantage_placement_state`) is no longer part of that comparison (the ad sets' own placements are still compared, and the aggregate is checked after the writes). The campaign name is never taken twice: a live campaign with the exact name counts as taken whatever its tag, a left-over known from the local name record counts even when the Meta listing misses it, and when the read of that campaign fails (not "does not exist"), it is retried 2-3 times over about 30 s and, if Meta still does not answer, the publish continues as a new campaign under the next free `<name> copy N` name (the name is never reused; a possible duplicate is accepted). Rate limits stay a stop. The stop message names the real copy name instead of "_2". Not detectable: no local record and a listing miss.
