## ACL-1822 — Rules Decision flow, review and human Apply/Undo — 2026-10-23

The Rules workspace presents the rule list and Split editor, Scope → Evidence →
Conditions → Action cards, assigned-object verdicts and reasons, an explicit Review
step and S1 stop-loss / S3 scale templates. Disabled, Observe and Suggest remain
the available modes; Automatic stays disabled until the rules executor task.
Country campaign tables expose the Rules cell and object inspector.

Apply and Undo use the existing human command preview, confirmation and read-back
flow. Undo restores the previous value from the saved, verified original command,
including currency units for budgets. It never trusts an older evaluator's value.
The local Rules API only prepares the inverse request and records a matching new
command result. Unknown undo results remain uncertain; they are not retried or
labelled Undone. Original and undo operation IDs stay in the journal. Backend,
loopback, owner, exact object/value and operation-reuse guards are retained.

Refresh preserves the current SVG navigation and Forms view alongside Rules.
The portable seed-escaping regression has a narrow JSON-data annotation rather
than moving the Rules tests into a Windows-only selection.

Offline full-dashboard regressions exercise both UI entry points in both themes
and at four widths, separate Apply/Undo confirmations, Cancel, verified status and
budget restoration, and no implicit parent activation. All command writes in these
tests use synthetic FakeMeta; no real advertising calls are made. The original
ACL-1816 evaluation-engine dependency remains separate and must complete its own
review, integration and delivery.
