## ACL-2533 — Instant Form templates: background image, uploaded from the builder — 2026-11-11

A form template can carry an optional background image, shown on the intro screen (`context_card.cover_photo_id`). In the Forms tab and in the builder's "Create and save form" the "Background image" field now has "Upload": choose a JPEG or PNG file (up to 8 MB) on this computer, see the preview at once, then press "Upload to Page". The preview is drawn from the local file only; nothing from Meta is loaded by the dashboard. The file is sent through the profile's own Ads Manager tab, as the chosen Page, with the same web request Ads Manager itself uses (not Graph); the Page must belong to the account. The template stores the photo id, the Page and the file's checksum, never the picture, so a republish on the same Page finds the form and uploads nothing again. "Choose from Page" and pasting a Photo ID stay as a fallback. One press makes one upload (one call in that session's budget), never retried; a failure after sending says the result is unknown. Meta's refusal is shown with the form name. A template without a picture is unchanged (same hash, same request).
Earlier in this task (ACL-2188 work): the picture needs a Description and belongs to one Page, and a template used on another Page stops at Check plan before anything is written. A changed picture makes a new form on the next publish. A cover that cannot be confirmed on a new form stops the run; on a reused form it is only noted. Clearing the picture now really removes it from the stored template.
Risk: the upload endpoint is an undocumented Ads Manager web request (not Graph) and can change without notice; the first live upload on a test Page (required parameters, whether the photo appears in the Page's photos or feed) is still to be done with the owner. A build older than this one shares the template library; it drops the picture when it validates a template, so it publishes a form without a picture under the old name and does not warn.
