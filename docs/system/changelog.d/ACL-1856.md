## ACL-1856 — Campaign creation keeps its progress and resumes only after a check — 2026-11-01

Publishing through the API now writes a small progress file for every campaign (next to the machine
config, `api_operations/`). It records what was about to be sent and which campaign, ad set, creative,
ad and image/video Meta confirmed. After a dashboard restart, a Stop or a lost answer, "Publish again"
first reads those objects back from Meta (same ad account, name, PAUSED campaign, still listed) and
continues only if they match; if one was renamed, moved or removed it stops, lists the IDs already
created and says what to fix, without writing anything. A write whose answer was lost is looked up
before it is ever sent again (uploads wait up to 10 minutes). If the progress cannot be saved, the
write is not sent. A repeated request with the same key and plan returns the same operation; the same
key with a different plan is refused. The result shows the partial IDs and one plain next action.
`ACL_OPERATION_JOURNAL=0` turns it off. [Task](https://github.com/MojoTheApe/adopy-campaing-launcher/issues/856).
