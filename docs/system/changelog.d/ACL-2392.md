## ACL-2392 — Builder: short plain-language errors, raw Meta text only in the details — 2026-11-05

Publish failures now show one short English line with the next step (for example "Targeting options were merged by Meta - replace the interests and republish") instead of raw Meta text, codes and ids. Unknown, unconfirmed and timed-out steps name the stage (for example "while creating ad set \"X\""). The raw text, codes, stage and readback lines now live in the header "Recent runs" popup (Show details expands per run, with a Copy details button; older history lines still render); the builder shows only the plain line, what was left in Meta and a "Details in Recent runs" link. `publish_history.jsonl` lines gain `failure` and `error_details`. New table and classifier in `src/fb_api/plain_errors.py`; `result_dict`/`dry_run_result` carry a `failure` object, `job["errors"]` holds the plain line and `job["error_details"]` the raw. Meta subcode 1870226 (reported by Meta as code 1 / http 500) is now a rejection once the readback proves nothing was written, so the rest of the job is no longer blocked. Readback mismatches show as one summary line. Gating (`publishable`, `blocking_failures`, `WritesBlocked`) is unchanged. Python changes need a `serve.py` restart; the template loads without one.
