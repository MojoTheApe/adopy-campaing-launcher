## Ownership and exact finalization

Read the complete real Issue and current requirements. Task-context assess emits
an exact Worker/main/scope identity; inspect code/decisions/related work/dependencies
and submit the real bounded ready assessment before work. A digest alone grants
no semantic readiness. Harmless exact terminal journal updates preserve scope;
criteria, needs and blocker edits do not. Old unprefixed proof is unchanged.

Work claims the actual Worker/session/branch/worktree through SHA CAS. Handoff
retains a nonauthorizing source snapshot with addressable worktree hash, original
owner/claim digest and source/scope/report bindings before any external status
write; final CAS removes Worker only after exact handoff reconciliation. All
unfinished task/capture handoffs retain branch OR worktree exclusion through fixes
and takeover. Raw local paths/tokens/reports stay out of the new ledger/history.
A copied digest/public operation ID never grants an owner or fresh effect.

An actual independent execution review-acquire reserves a source Reviewer. Direct
review-plan emits the precise full-scope/source/main/policy identity. Inspect all
scope, files and applicable native checks, add scope_review/checks/report (and
capture mandate), then record-review. The Reviewer cannot be any retained author.
Direct begin with that same genuine Reviewer/session/claim acquires the one
integration reservation. Other real integrations wait; independent source reviews
can continue. Direct tasks never become Approved or a synthetic batch. Batch
engineering retains actual approval/intake/frozen composition/integration review.

Use the actual project-owned pinned client. `direct begin` is an owned CAS
reservation write, not a preview or a merge. For a reviewed-merge task:

```sh
python3 scripts/task_tracker.py direct begin --pr SOURCE_PR --actor Reviewer-R001 --session ACTUAL_REVIEW_RUN --coordinator Coordinator-C001 --claim ACTUAL_REVIEW_CLAIM
```

For a real task with separately authorized package/production delivery, bind the
actual verifier workflow and native job on the **initial** reservation:

```sh
python3 scripts/task_tracker.py direct begin --pr SOURCE_PR --actor Reviewer-R001 --session ACTUAL_REVIEW_RUN --coordinator Coordinator-C001 --claim ACTUAL_REVIEW_CLAIM --deliver --delivery-workflow .github/workflows/ACTUAL_DELIVERY.yml --delivery-job 'ACTUAL_NATIVE_VERIFICATION_JOB'
```

This selects no delivery policy, dispatches no workflow and proves no installed
outcome. The portable receipt writer still verifies actual native workflow/job,
merge and target proof after the source receipt/status/release. An existing
reservation without authorization cannot gain it silently later. A genuine owned
source fix invalidates its old authorization; after fresh independent review the
same owner must explicitly repeat the full delivery-authorized `direct begin`
command to renew the binding to the revised source. Do not reuse an old verifier
identity or report as proof of the revised source. Capture has no such delivery
authorization; use tracked engineering for an external target.

Stage off enters main. Stage on enters the configured permanent Stage, records
actual stage, performs exact target verification, records verify-stage, and admits
unchanged promotion. The source subject is retained; Git-only n8n Stage grants no
runtime operation. Main/source/scope changes require genuine author return/fix or
real unchanged-source compatibility. Full native checks and branch protections
remain mandatory; unsupported CI proof is missing, not reusable coverage.

After actual admitted main, the maintained merged path durably records original
accepted scope, reconciles actual task status while Reviewer/reservation are
held, then atomically archives/releases. An absent pointer without exact archive
is an error. There is no standalone early direct finish. Crash/unknown CAS or
partial label response requires same-operation fresh read/reconciliation, not a
new claim/receipt or timeout. Package/production/publication still pending after
source release remains unfinished in shared completion/dependencies/readiness.

## Ordinary-note capture

Only a prior reviewed knowledge_capture_policy permits this exception. Roots are
normalized ordinary-note directories disjoint from governance/runtime/tool roots;
parents such as docs/ cannot include protected docs/repository or docs/runtime.
A regular .md/.txt extension is necessary, never sufficient. Complete immutable
before/after trees/blobs/modes and actual semantic assessments cover every change.
No Issue is created per ordinary note or grouped note capture.

Save a random public32hex capture ID before capture begin. Use a dedicated
codex/capture-ID branch and actual Worker/session/Coordinator/worktree. The ID is
not a secret claim and cannot be passed to Issue APIs, timers/dependencies/releases
or a dummy task. Begin atomically records operation and actual Worker before PR
creation. Capture pr requires exact title [Capture ID] Summary, one Tracker capture:
ID line, no Tracker issues line, --body-file, --journal-file and --apply. Only the
fresh confirmed barrier CAS winner may POST; ambiguous CAS/response or process
restart is GET-only. Unknown effect keeps the original owner. Reconcile the exact
native --pr/request; equivalent/unattributed or multiple possible PRs do not settle
it. No timeout/HTTP status proves no effect. Direct human mutations cannot be
prevented globally; residual cross-system races are not claimed absent.

Capture assess first emits its complete scope/mandate/Worker identity. Inspect
content/mandate, add the real report and verdict within-mandate, needs-engineering
or unknown, and apply. Only within-mandate can hand off; this is operator
attestation, not a machine certification of arbitrary prose. Governance, AGENTS,
CLAUDE, SKILL, README/index/routing, structure, automation/configuration, executable
or mixed effects, rename/delete, unsafe modes/paths, binary/oversized or truncated
content require tracked engineering. A note cannot enable its own mandate. The
independent source Reviewer separately assesses the entire immutable delta and
mandate. Role or filename grants no review exception.

Capture handoff then normal execution review-acquire/record-review/direct begin
retain normal pools and selected Stage. A batch-selected project serializes this
explicit singleton exception against actual batches. Capture finish previews the
actual main acceptance; apply needs the genuine retained Reviewer and
--reviewed-complete. It writes its one operation receipt and explicit no-Issue
status before archive/release, never fabricated Merged/Done labels. External
publication/package/production capture is unsupported; use a tracked task.

The operation ledger stores only allowlisted structural facts/digests, independent
implementer identities, immutable scopes/review references, PR intent and receipt
history. Public consumer state is not inherently confidential. Keep raw note,
assessment, diagnostic/instruction text and private source references outside it.
The board shows only safe public task/capture references and actual same-repo PR
links. Capture consumes capacity without a fake task row or clock. Stale/unknown
projection never implies available capacity.

## Exact recovery and portable boundary

`capture pr` defaults to preview; `--apply` is the one-effect request path. Save
the public ID and prospective journal outside Git, retain the returned claim,
and supply the exact Worker/session/Coordinator/branch/worktree on begin, work,
assess, handoff and stop. A completed handoff replay compares those supplied
components and original token; a public ID or digest never grants a new effect.
For a lost PR response, inspect the saved journal and native matching candidates,
then use the same current owner, exact original title/body/purpose and `--pr`
with `capture pr --apply`. This is GET-only reconciliation, including after an
actual main merge. An unknown promotion must be reconciled before admission,
finish or stopped-Reviewer transfer; merging alone does not attribute its POST.

`capture finish --capture PUBLIC_ID --pr MAIN_PR` previews the actual acceptance.
Apply with `--apply --reviewed-complete` and the genuine retained Reviewer actor,
session, Coordinator and claim. Retry the same finish after ambiguous CAS; it
reconciles the durable receipt/status journal before release. Task finalization
uses the normal `merged TASK_ID --pr MAIN_PR` preview and reviewed apply. Current
Task status/scope is re-read after the final admission; a changed status or scope
holds ownership and requires reconciliation. No direct early-release command is
provided. Cancel is limited to an owned operation with proven unmerged closed
source or no dispatched request, never an unknown effect or changed Stage/main.

Both raw and separated helper layouts carry12/24 exact artifacts, including the
canonical `tracker_direct_policy.py`; format1 adds `route_validator` and explicit
execution4/context2/capture1 capabilities. Python3.9 portable admission/receipt
readers reject malformed, partial, unknown and unfenced modern state before
effects. The immutable3.6 reader refuses7 and held3/base7. Keep all mandatory
layers and retry history; a selected config is not state activation.

Capture CI reuse and retry remain unsupported: a capture cannot be represented
by an empty Issue scope, dummy number or relabeled generic-main proof. Fresh full
applicable checks remain required. Modern task/batch retry on current main needs
one exact actual same-repository merged PR association and its real scopes and
composition; unknown, ambiguous, foreign or capture associations stop before
retry authority. Existing wire6 history/budgets are unchanged. No failed-only or
mixed-attempt capability is added.

If helper changes alter the canonical CI producer bytes, a selected project must
refresh its real copied producer blob and reviewed workflow/policy in its own
source change. Old native proof never becomes proof from the new producer merely
through a new engine pin. Publication of engine support, compatible Master and
skill, readers, consumer source adoption and owned state activation are separate
