# Как записывать codegen через уже открытый Multilogin-профиль

Обычный `playwright codegen <url>` открывает **свой собственный, новый**
Chromium — не тот, что управляется Multilogin. Это плохо по двум причинам:

1. **Безопасность.** Новый браузер не залогинен в Facebook — если логиниться
   заново прямо во время записи, пароль попадает в сгенерированный файл в
   открытом виде. Это уже случалось дважды в одной из прошлых сессий, оба
   файла пришлось удалить (см. `agent10-post-conversion-location-handoff.md`).
2. **Антидетект.** Meta видит запись как совершенно новое устройство/браузер
   без истории профиля — не тот "отпечаток", что настроен в Multilogin для
   этого аккаунта.

Ниже — как получить codegen-подобную запись **на том же самом окне**, что
уже открыто и залогинено в Multilogin, без второго браузера.

## Вариант A (уже реализован в репозитории): `click_recorder.py`

`src/fb_ads_rpa/click_recorder.py` уже делает почти это:

- Подключается через CDP к уже открытому браузеру (`_find_cdp_url()`
  сканирует известные порты Multilogin/Chrome).
- Внедряет JS-слушатель кликов/изменений/клавиш прямо в открытую вкладку —
  **без** открытия нового окна.
- Пишет JSON-"рецепт" в `output/rpa_recipes/` с полем `own_text`, `role`,
  `aria_label`, `css_path`, координатами — то же самое, чем мы вручную
  пользовались весь день при разборе скриншотов.

Управляется через дашборд (`POST /rpa-record/start`, `/stop`, `GET /status`,
`/recipes` — уже подключено в `src/web/app.py`).

**Плюс:** уже работает, ничего писать не надо.
**Минус:** выдаёт JSON с описанием действий, а не готовый Playwright-код
(`page.get_by_role(...).click()`) — для переноса в `meta_dom.py` всё равно
нужно вручную превратить описание в селектор (хотя это уже большая часть
работы, которую раньше делали по скриншотам вслепую).

## Вариант B (рекомендуется для настоящего codegen): `page.pause()` на CDP-сессии

Playwright умеет открыть **Inspector** (то самое окно с живой генерацией
кода, что и у `codegen`) на уже существующей странице — если к ней
подключиться через `connect_over_cdp()` (то же самое, что уже делают
`browser.py::_connect_playwright()` и все провайдеры в этом файле) и
вызвать `page.pause()`.

```python
# scripts/codegen_via_multilogin.py (набросок, ещё не создан)
from playwright.sync_api import sync_playwright

# CDP URL уже открытого Multilogin-профиля -- переиспользуй существующую
# логику поиска, а не гадай порт руками:
#   from src.fb_ads_rpa.click_recorder import _find_cdp_url
#   cdp_url = _find_cdp_url()
# либо ещё надёжнее -- через уже готовый провайдер, который умеет
# ПОДКЛЮЧИТЬСЯ к уже открытому профилю, не перезапуская его:
#   from src.fb_ads_rpa.browser import get_browser_provider
#   conn = get_browser_provider("multilogin_attach").open(entry, account_label)
#   cdp_url = f"http://127.0.0.1:{conn.debug_port}"

cdp_url = "http://127.0.0.1:PORT"  # см. варианты выше

with sync_playwright() as p:
    browser = p.chromium.connect_over_cdp(cdp_url)
    context = browser.contexts[0]
    page = context.pages[0] if context.pages else context.new_page()
    page.pause()  # открывает Playwright Inspector НА ЭТОЙ ЖЕ странице
```

Когда откроется Inspector:
1. Нажать "Record" (если не включено по умолчанию).
2. Кликать руками в **том же самом** окне Multilogin, что было открыто —
   окно не меняется, не открывается второе.
3. Inspector в реальном времени показывает сгенерированный Python-код
   (`page.get_by_role(...)`, `page.get_by_text(...)` и т.д.) — тот же
   формат, что и у обычного `codegen`.
4. Скопировать код из панели Inspector, вставить в
   `output/codegen_<название>.py` для дальнейшего разбора и переноса в
   `meta_dom.py` — тем же способом, каким уже перенесена вся текущая
   `run_recorded_campaign_flow()`.
5. Закрыть Inspector (продолжить выполнение) — браузер остаётся открытым и
   залогиненным, как был.

### Почему это безопаснее, чем обычный `codegen`

- Страница уже открыта и залогинена **до** вызова `page.pause()` — процесс
  логина никогда не происходит внутри записи, значит пароль физически не
  может попасть в код (в отличие от прошлого инцидента, где логин
  происходил уже ВО ВРЕМЯ записи в отдельном codegen-браузере).
- Это тот же самый Multilogin-профиль/отпечаток, никакого нового
  "устройства" с точки зрения Meta.

### Требование, которое нужно соблюдать всегда

Даже с этим методом — **если по какой-то причине откроется экран логина
Facebook во время записи** (протухла сессия, разлогинило), procedure та же,
что и раньше: не логиниться внутри записи; закрыть Inspector, залогиниться
руками отдельно, начать запись заново после успешного логина.

## Как получить CDP-адрес уже открытого профиля (готовые функции, не гадать порт)

Не нужно писать поиск порта с нуля — уже есть три рабочих варианта в
`src/fb_ads_rpa/`:

| Функция | Файл | Когда использовать |
|---|---|---|
| `_find_cdp_url()` | `click_recorder.py` | Быстро, сканирует известные порты, не требует знать `profile_id` |
| `MultiloginAttachOnlyProvider().open(entry, account_label)` | `browser.py` | Надёжнее — подключается к УЖЕ открытому профилю по `profile_id` из `ad_account_map.csv`, никогда не перезапускает вручную открытый профиль |
| `MultiloginDirectCDPProvider()._discover_debug_port(...)` | `browser.py` | Низкоуровневый — читает `DevToolsActivePort` файл профиля напрямую |

Для разовой записи codegen предпочтительнее `MultiloginAttachOnlyProvider`
— он уже реализует всю логику "подключиться к открытому, не трогать, если
занято" и возвращает готовый `debug_port`.

## Итог: когда какой вариант использовать

- **Нужно быстро посмотреть, что именно кликнул человек** (roles/aria/
  own_text) для последующего ручного переноса в код → вариант A
  (`click_recorder.py`, уже работает через дашборд).
- **Нужен готовый Playwright-код, который почти без правок можно вставить
  в `meta_dom.py`** (как это было со всей текущей `run_recorded_campaign_flow`)
  → вариант B (`page.pause()`), пока не реализован как отдельный скрипт —
  создать `scripts/codegen_via_multilogin.py` по наброску выше, когда
  понадобится.
