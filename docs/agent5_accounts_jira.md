# Агент 5: аккаунты + задачи в Jira

## Назначение

Агент читает список аккаунтов из книги **Upluad FB.xlsx** (лист **Accounts**), для отобранных строк **составляет** задачу (Summary + Description) по шаблону.

- **Режим по умолчанию:** скрипт открывает в браузере страницу создания задачи в Jira, копирует описание в буфер обмена и выводит Summary в консоль. Ты вставляешь данные и **публикуешь задачу вручную**. Один аккаунт — одна задача.
- **Режим `--api`:** создание задачи через Jira API. **Excel не изменяется** — ссылки в док (столбец Link) автоматически не вписываются. Нужны переменные окружения `JIRA_EMAIL` и `JIRA_API_TOKEN`.

**Источник данных:** `Upluad FB.xlsx` (путь задаётся в `config/paths.py` или переменной окружения `UPLOAD_FB_EXCEL`).

---

## Условие отбора строк

Обрабатываются только строки листа **Accounts**, у которых:

- столбец **Link** пустой (или пробелы/NaN);
- в столбце **Asset** есть значение (не пусто).

Остальные строки пропускаются.

---

## Правило Summary (заголовок задачи Jira)

Формат:

```text
{Brand} - {Asset} LPs for {Account} - {CountryCode} - Media
```

- **Brand:** только для Колумбии (код страны **CO**) → `Suxxess FX`; для всех остальных стран → `Algobi`.
- **Asset:** значение из столбца **Asset** листа Accounts (бренд+оффер, в Excel уже через вилукап).
- **Account:** значение из столбца **Account** листа Accounts.
- **CountryCode:** код страны, извлекаемый из имени аккаунта (например из «FacebookUL574 EC Fav» берётся код **EC**; см. раздел «Код страны» ниже).
- Суффикс всегда: ` - Media`.

**Пример:**  
`Algobi - Banco Industrial LPs for FacebookUL574 EC Fav - EC - Media`

---

## Код страны из имени аккаунта

Код страны — два символа (CO, EC, GT, MX и т.д.). В имени аккаунта он обычно идёт после названия аккаунта (например «FacebookUL574 **EC** Fav» → **EC**).

В коде используется правило: в строке **Account** ищется известный двухбуквенный код из списка (CO, EC, GT, MX, …). Если найден — он подставляется в Summary. Если не найден — используется первый такой код, который встретится в строке, или запасное значение (например «XX»), описанное в коде/конфиге.

---

## Description (тело задачи Jira)

Текст для поля **Description** берётся из листа **Main**:

- В **Main** ищется строка, где в первом столбце (имя аккаунта) совпадает значение **Account** из обрабатываемой строки Accounts.
- Из этой строки Main читаются ячейки, из которых в Excel собирается тело задачи (несколько столбцов подряд), и объединяются в один текст для Description.

Если строки с таким аккаунтом в Main нет, в коде используется запасной вариант: сборка описания по шаблону из полей текущей строки Accounts (Domain, Account, Asset, код страны и т.д.) или явный список индексов столбцов Main для «образцовой» строки.

## Поля задачи в Jira (источник данных)

| Поле Jira      | Источник / правило |
|----------------|--------------------|
| **Project**    | MAR (ключ проекта) |
| **Issue type** | Marketing / Create Funnel (как в шаблоне) |
| **Summary**    | По формуле выше: Brand, Asset, Account, CountryCode, « - Media» |
| **Description**| Из Main по совпадению Account или по шаблону из Accounts |
| **Priority**   | Medium |
| **Team**      | Media |
| **Brand**     | Algobi или Suxxess FX (по коду страны CO) |
| **Assignee**  | Automatic (если есть в проекте) |
| **Reporter**  | Evgeni Sedin (или текущий пользователь по API) |
| **Labels**    | **Limited_QA** (всегда) |
| **Team (migrated)** | **Media** (всегда; id поля подставляется по API или через JIRA_TEAM_FIELD_ID) |

Остальные поля (если нужны) задаются в коде по тому же шаблону. Точные ID полей в Jira Cloud могут отличаться (custom fields); при необходимости их уточняют в настройках проекта MAR.

## Jira API: URL и авторизация

- **Base URL:** `https://mar-adopy.atlassian.net`
- **Пример задачи:** `https://mar-adopy.atlassian.net/browse/MAR-38466`
- **Проект:** MAR  
- **Создание задачи:** REST API, например `POST /rest/api/3/issue` (или `/rest/api/2/issue` для старого формата).

Jira Cloud использует авторизацию по **email + API token** (Basic Auth или Bearer). Токен **не хранить в коде** и не коммитить в репозиторий.

---

## Инструкция: создание и хранение Jira API token

1. Зайти в управление профилем Atlassian:  
   **https://id.atlassian.com/manage-profile/security/api-tokens**
2. Нажать **Create API token**.
3. Ввести метку (например «fb_agents») и скопировать выданный токен (он показывается один раз).
4. Сохранить токен в переменной окружения:
   - **Имя переменной:** `JIRA_API_TOKEN`  
   - **Значение:** вставленный токен (без кавычек в значении).
5. Для Basic Auth также нужен email учётной записи Atlassian. Задайте переменную **`JIRA_EMAIL`** (тот же email, которым вы входите в Jira). Пример: `JIRA_EMAIL=evgeni.s@adopy.com` (подставьте свой рабочий email).

В коде скрипт читает `JIRA_API_TOKEN` и `JIRA_EMAIL` только из окружения и не записывает их в репозиторий и логи.

## Обратная запись в Excel

Скрипт **не записывает** ссылки на задачи в Excel (ни в режиме браузера, ни при `--api`). Ссылки в столбец **Link** при необходимости добавляешь вручную.

## Запуск агента 5

Из корня репозитория:

```bash
# Режим по умолчанию: открывает страницу создания задачи в браузере, вставляешь Summary и Description и публикуешь сам
python run_jira_from_accounts.py

# Просмотр списка задач без открытия браузера
python run_jira_from_accounts.py --dry-run

# Создание задач через API и запись Link в Excel (нужны JIRA_EMAIL и JIRA_API_TOKEN)
python run_jira_from_accounts.py --api

# Пауза после каждого аккаунта (ждать Enter перед следующей вкладкой)
python run_jira_from_accounts.py --pause
```

Переменные окружения **`JIRA_EMAIL`** и **`JIRA_API_TOKEN`** нужны только для режима **`--api`**.

## Открытие пустой формы Jira и вставка текста

- **Если по умолчанию открывается не пустая форма** (например, сначала другая страница и нужно жать «Next»): один раз открой в Jira страницу создания новой задачи так, чтобы была видна пустая форма (Summary + Description). Скопируй адрес из строки браузера и задай его в переменной окружения **`JIRA_CREATE_ISSUE_URL`**. Тогда скрипт будет открывать именно эту ссылку.
- **Если в Jira ничего не вставилось из буфера:** скрипт каждый раз сохраняет Summary и Description в файл **`output/jira_task_paste.txt`**. Открой этот файл и скопируй оттуда: первый блок — в заголовок, второй — в тело задачи.

Подробнее см. **README.md** и код в **src/jira_agent/jira_from_accounts.py**.
