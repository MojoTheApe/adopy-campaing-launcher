# План: инфраструктура агентов для управления FB-кампаниями

Общий план и «с чего начинали». Не терять общую картину при работе над отдельными агентами.

---

## Контекст

- Опыт с Cursor/кодом: нет, нужно всё разжёвывать.
- Уже есть: рабочий агент в **Make.com** (парсит данные, выдаёт связки); готовый **Excel** со всеми шаблонами для постройки остальных агентов.
- Цель: несколько агентов, которые вместе закрывают полный цикл управления кампаниями в Facebook.

---

## Что уже сделано в первом агенте (fb_agents / analysis agent)

По сути закрыты пункты **1–4** в одном агенте:

| # | Задача | Статус в агенте 1 |
|---|--------|-------------------|
| **1** | Анализ данных (~7000 строк Excel, ~10 столбцов); промпт «как читать данные» — его нужно тюнить под чёткие результаты | Реализовано: чтение Excel, парсинг адсетов, обогащение (Offer из Ad Asset), метрики. Промпт/правила можно дорабатывать. |
| **2** | Выдача лучших связок + кампаний на потенциальный скейлинг | Реализовано: комбо Strong/Interesting по странам, топ-N кампаний на оффер по странам, сравнение по офферам. |
| **3** | Запоминание данных по аккаунтам и их активности; анализ прогресса/деградации кампаний | Частично: анализ по текущему срезу есть; «запоминание» и сравнение во времени (история) в коде пока нет — нужен отдельный шаг (хранилище + сравнение). |
| **4** | Помощь в приоритетах и распорядке: что делать, чтобы больше депозитов или выше value депозитов | Реализовано в виде отчётов и рекомендаций (CM по странам, офферы, топ-кампании); явный «ежедневный приоритет-лист» можно добавить поверх. |

**Итог:** анализ, связки, скейлинг-кандидаты и база под приоритеты — в одном агенте; история и «память» — запланировать отдельно.

## Что нужно спланировать и запомнить (пункты 5–9)

| # | Задача | Суть | Зависимости |
|---|--------|------|-------------|
| **5** | Управление списком аккаунтов (домены, пиксели) + автоматическое открытие тасок в **Jira** по шаблону | Один источник правды по аккаунтам; по списку/правилам — создание задач в Jira по заданному шаблону. | Список аккаунтов, шаблон задачи Jira, доступ к Jira API (или интеграция через Make.com). |
| **6** | Отслеживание готовности тасок в Jira + открытие кампании в **Kitaro** (трекинг) по шаблону | Когда таска в Jira готова (статус/условия) — создание кампании в Kitaro по шаблону. | Шаблон кампании в Kitaro, API/интеграция Kitaro и Jira. |
| **7** | После согласования с тобой — брать **лучшие связки** (из п.2) и дальше с ними работать | Флоу: связки из агента 1 → твоё согласование → передача выбранных связок в следующие шаги (например в п.8 или в таски). | Чёткий формат «согласованных связок» и куда они подаются. |
| **8** | Сбор **кампании** для поднятия с Excel в FB; шаблон в Excel готов (все закономерности там) | Заполнение/сбор данных по шаблону Excel и выгрузка/загрузка в FB (или подготовка под загрузку). | Твой Excel-шаблон, понимание, откуда брать данные (связки, аккаунты, креативы). |
| **9** | Ежедневный таск-менеджер и тест follow-up для команды | Ежедневные задачи для команды + отслеживание тестов и последующих действий. | Правила «кто что делает», форматы задач, где хранить (Jira/другое). |

## Порядок и формат работы

1. **Этот документ** — зафиксированный план в репозитории; при работе над агентами 2+ опираться на него.

2. **Дальше — в формате диалога** по каждому пункту (5 → 6 → 7 → 8 → 9):
   - уточнить цель и границы («что именно должен делать этот агент»);
   - проверить, что есть (Make.com, Excel, шаблоны Jira/Kitaro);
   - решить, где живёт логика: Cursor/код, Make.com, или связка обоих;
   - расписать шаги внедрения по шагам, без кода или с минимальным кодом и пояснениями.

3. **Пункты 5 и 6** — логично идти подряд: сначала список аккаунтов + Jira (5), потом «готовность в Jira → Kitaro» (6). Перед этим уточнить: шаблоны задач в Jira и кампаний в Kitaro уже есть в виде описания/скринов или только в голове?

4. **Пункты 7 и 8** — связки из п.2 → твоё согласование (7) → передача в «сбор кампании в Excel под FB» (8). Имеет смысл описать формат «согласованной связки» (поля, откуда брать оффер/креатив/таргет) и как этот формат стыкуется с Excel-шаблоном для FB.

5. **Пункт 9** — отдельный поток: ежедневные таски + тест follow-up. Уточнить: задачи создаются в Jira, в другом инструменте или только список/напоминания; кто «команда» и что значит «тест follow-up».

## Следующий шаг

Выбрать пункт для детальной проработки (рекомендуется начать с **5** или с того, что приоритетнее) и в диалоге: уточнения → проверка → пошаговый план по выбранному пункту.
