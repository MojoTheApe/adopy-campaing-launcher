# Агент 6: Jira → Kitaro

**Цель:** когда таска в Jira готова (нужный статус/условия) — создавать кампанию в Kitaro (трекинг) по шаблону.

**Зависимости:**
- Шаблон кампании в Kitaro (какие поля, откуда брать данные).
- Способ проверки «таска готова» в Jira (статус, переход, метка и т.п.).
- Доступ к Kitaro: API, веб, или только ручные шаги по инструкции.

---

## Вопросы для уточнения (перед реализацией)

1. **Jira — когда считаем задачу «готовой»?**
   - Конкретный статус (например «Done», «Ready for Kitaro»)?
   - Или переход по workflow (например «Approved»)?
   - Нужно ли отслеживать только задачи, созданные агентом 5 (MAR, Limited_QA, Media), или любые по фильтру?

2. **Kitaro — как создаётся кампания?**
   - Есть ли у Kitaro API для создания кампании? (URL, документация, токены.)
   - Или процесс такой: открываешь Kitaro вручную, подставляешь данные из Jira/Excel по шаблону? Тогда агент может: готовить данные (ссылка на Jira, домен, оффер и т.д.) и открывать страницу создания кампании с подсказками.

3. **Какие данные из Jira/Excel должны попасть в кампанию Kitaro?**
   - Например: домен, оффер (Asset), страна, ссылка на LP, что ещё?
   - Есть ли готовый шаблон кампании в Kitaro (скрин, список полей) или описание в Excel/документации?

4. **Где должна жить логика агента 6?**
   - В коде (Python в fb_agents): опрос Jira API → при «готово» вызов Kitaro API или формирование данных + открытие URL.
   - В Make.com: сценарий Jira → Kitaro.
   - Связка: скрипт готовит данные/файл, Make или вручную переносят в Kitaro.
